# OKO — видеоконтроль кассовой дисциплины

Сервис для Datathon 26. Проверяющий загружает видео с камеры над кассой (можно пачкой), а OKO
выдаёт вердикт и для каждого эпизода — тип, таймкод, 1–3 кадра-доказательства, описание того,
что видно, и пункт нормативного акта РК. Модели работают на сервере команды, облачные AI-сервисы
не используются. Интерфейс на трёх языках (ҚАЗ / РУС / ENG) в пиксельном стиле Datathon.

**Что готово:** обязательный контур ТЗ (интерфейс, API для жюри, очередь с дедлайном,
кадры-доказательства, каталог норм со сверенными пунктами) и рабочие инструменты для проверяющего:
пакетная загрузка, уведомления, история, разбор эпизодов, отчёт для печати, сводка.
**Чего не хватает:** детекторов. Сейчас есть один детектор без обучения — «камера перекрыта» (V13).
Остальные типы ждут моделей команды, место под них готово (раздел «Куда встраивать модели»).

## Обязательные требования ТЗ → где в коде

| Требование (ТЗ) | Где |
|---|---|
| Веб-интерфейс: загрузка, статус, результат без ручного запуска кода | `GET /`, исходники в `app/static/ui/` |
| Вердикт: «Нарушение не обнаружено» / «Обнаружены признаки возможных нарушений» | `app/pipeline/analyzer.py` |
| По каждому нарушению: тип, таймкод, описание, 1–3 кадра JPEG/base64 | `analyzer.py`, `evidence.py` |
| Правило и источник: документ и пункт | `app/rules/catalog.py`, вкладка «Нормы» |
| API: `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`, ключ `X-API-Key` | `app/main.py` |
| Ответ не позже чем через 5 минут, в том числе когда видео приходят пачкой | дедлайн от момента загрузки, `app/jobs.py` |
| Локальность и переносимость | всё в одном процессе, шрифты и иконки встроены в страницу |
| Лица не распознаются | пикселизация лиц на кадрах, роли — по одежде и позиции |

## Инструменты для проверяющего

| Что | Как работает |
|---|---|
| Очередь и нагрузка | Пул из `OKO_WORKERS` потоков, бюджет считается от загрузки. Статус очереди и устройство (GPU/CPU) видны в шапке и на вкладке API. `scripts/smoke_test.py --parallel 5` — нагрузочный тест как у жюри. |
| Пакетная загрузка | Несколько файлов за раз. По каждому видна своя полоса прогресса: загрузка → очередь → анализ → готово. Внизу хотбар с ячейками пакета. |
| Поля при загрузке | Отделение, касса и дата съёмки. Сохраняются в журнале и используются в фильтрах и сводке. |
| Уведомления | Если вкладка в фоне, когда отчёт готов, приходит системное уведомление браузера; клик открывает отчёт. Если открыта — всплывающее сообщение на странице. В заголовке вкладки виден счётчик непросмотренных отчётов. Всё работает в браузере, данные никуда не уходят. |
| История | Все проверки с фильтрами по файлу, отделению, кассе, вердикту, статусу разбора и датам. Новые отчёты подсвечены, пока их не открыли. Отметка «просмотрено» хранится на сервере. |
| «Смотреть» | По кругу проигрывает 3 секунды до и после таймкода. Если браузер не может проиграть файл или отчёт открыт из истории (видео уже удалено), показываются кадры клипа, сохранённые на сервере (4 кадра/с). |
| Горячие клавиши | ←/→ — соседний эпизод, Y — подтвердить, N — ложное срабатывание, W — смотреть, C — комментарий, P — отчёт. Работают и в русской раскладке. |
| Разбор эпизода | Кнопки «Подтвердить» и «Ложное срабатывание», комментарий сохраняется автоматически. |
| Отчёт для служебной записки | Печатная форма A4: данные проверки, кадры, таймкоды, пункты с цитатами, решение проверяющего, место для подписи. Печать или «Сохранить как PDF» в окне печати. Прямая ссылка: `/report/<job_id>`. |
| Сводка | Проверено видео, с нарушениями, эпизоды, подтверждено, ложные, доля ложных; графики по типам и дням, таблица по отделениям. |
| Языки | ҚАЗ / РУС / ENG. По умолчанию русский, выбранный язык запоминается. Тексты норм и ответ API всегда на русском: это официальная редакция актов. |

## Быстрый старт

```bash
pip install -r requirements.txt
OKO_API_KEYS=придумайте-длинный-ключ uvicorn app.main:app --host 0.0.0.0 --port 8000
# открыть http://localhost:8000
```

Если `OKO_API_KEYS` не задан, ключ сгенерируется сам и сохранится в `data/api_key.txt`.

Через Docker:

```bash
cp .env.example .env        # впишите свой ключ
docker compose up --build
```

Uvicorn запускайте **одним процессом**: очередь задач живёт в его памяти. Сколько видео
обрабатывается параллельно, задаёт `OKO_WORKERS`.

### Проверка, что всё работает так, как ждёт жюри

```bash
python scripts/make_test_video.py --out data/test_covered.mov --cover 5:8   # видео с перекрытой камерой
python scripts/smoke_test.py --url http://localhost:8000 --key <ключ> --file data/test_covered.mov --parallel 5
```

`smoke_test.py` проверяет: 401 без ключа, `job_id`, ответ меньше чем за 300 с, схему JSON,
согласованность `verdict` и `violations`, что кадры — настоящие JPEG и что в `description` есть
пункт. Печатает медиану, p95 и максимум времени ответа. На CPU пять параллельных видео по 145 с
обработались не дольше чем за 32 с (пока работает только лёгкий детектор).

Оценка на датасете (`X-1` на латинице и `Х-1` на кириллице считаются одним видео):

```bash
python scripts/eval_labels.py --videos ./dataset --labels open_labels.xlsx --local
```

## Публичный URL

- **Для отладки:** `cloudflared tunnel --url http://localhost:8000` даёт адрес `https://….trycloudflare.com`. При перезапуске он меняется.
- **Для сдачи:** своя машина или VPS с GPU, домен и Caddy: `caddy reverse-proxy --from oko.example.kz --to localhost:8000`. HTTPS настроится сам.
- Уведомления браузера работают только по HTTPS или на `localhost`.
- Аренда GPU-сервера — это не облачный AI API, но правило о дисквалификации строгое. Подтвердите у организаторов письменно.

## Как устроено

```
браузер / жюри
  │  POST /api/v1/analyze  (.mov, X-API-Key)        POST /ui/v1/analyze (интерфейс + отделение/касса/дата)
  ▼
app/main.py ── сохраняет файл ──► app/jobs.py: очередь, OKO_WORKERS потоков, дедлайн от загрузки
                                     │
                                     ▼
                          app/pipeline/analyzer.py
  1. кадры с частотой OKO_SAMPLE_FPS (video.py)
  2. детекторы → кандидаты {rule_id, время, уверенность, «что видно»}
  3. склейка повторов; уверенность ≥ OKO_THRESHOLD и есть сверенный пункт → в API,
     от OKO_REVIEW_THRESHOLD до порога → «на проверку» (только в интерфейсе)
  4. кадры-доказательства (evidence.py): главный, «до», «после», рамки, пиксели на лицах
  5. description = что видно + почему это может быть нарушением + документ и пункт из каталога
  6. после ответа — клипы ±3 с для «Смотреть» (clips.py, только загрузки через интерфейс)
                                     │
                                     ▼
GET /api/v1/jobs/{id} → JSON строго по схеме ТЗ (app/views.py)
```

Журнал проверок — по папке на проверку в `data/jobs/<id>/`:

| Файл | Что внутри |
|---|---|
| `api.json` | ответ API строго по схеме ТЗ |
| `ui.json` | отчёт для интерфейса: кадры, превью по секундам |
| `meta.json` | отделение, касса, дата, вердикт, эпизоды, решения проверяющего, «просмотрено» |
| `clips.json` | кадры ±3 с вокруг каждого эпизода |

Видео после анализа удаляется (`OKO_KEEP_VIDEOS=false`). Базы данных нет: история читается из
`meta.json` при старте. Сводка считается в браузере из истории — для тысяч проверок этого хватает.

Служебные запросы интерфейса (без ключа, как и сама страница):
`/ui/v1/history`, `/ui/v1/jobs/status?ids=…`, `/ui/v1/jobs/{id}`, `…/review`, `…/seen`, `…/clip/{key}`, `/ui/v1/status`.

## Куда встраивать модели

Детектор — это класс в `app/pipeline/detectors/` с тремя методами:

```python
class CVRulesDetector(Detector):
    name = "cv_rules"

    def begin(self, ctx):                 # перед видео
        self.cashier_seen = []

    def on_sample(self, sample, ctx):     # каждый кадр: sample.t, sample.frame (BGR), sample.small
        ...                               # люди, руки, деньги, телефон → зоны → состояние

    def end(self, ctx):                   # после видео → кандидаты
        return [Candidate(rule_id="V03", t_start=44.2, confidence=0.82,
                          observed="В 0:44 кассир выходит из кабины, клиент остаётся у окна",
                          evidence_times=[44.2, 43.0, 46.0],
                          boxes={44.2: [Box(0.4, 0.1, 0.6, 0.4, "место кассира пусто")]})]
```

Затем добавьте класс в `REGISTRY` в `detectors/__init__.py`, а имя — в `OKO_DETECTORS`.
Заготовка для локальной VLM (например, Qwen3-VL, Apache-2.0) — `detectors/vlm_stub.py`.
`OKO_DEVICE=cuda` принудительно включает GPU-режим, а статус GPU виден в интерфейсе.

Правила для детекторов:

- `rule_id` берётся только из каталога. Документ и пункт подставляет `catalog.py`, модель их не пишет.
- В `observed` пишется только то, что видно на кадре. Без «украл», «умышленно», без сумм и личностей.
- Тяжёлые модели загружайте один раз на процесс, на уровне модуля. Следите за `ctx.time_left()`.
- Ultralytics YOLO распространяется под AGPL-3.0. Без согласования с организаторами его не берите, безопаснее RF-DETR (Apache-2.0).

## Интерфейс: где что лежит

```
app/static/ui/
  page.html    разметка (фрагмент без <html>, его же можно опубликовать как статическое демо)
  style.css    стиль: космос, Monocraft, кнопки с двойной обводкой, хотбар
  i18n.js      тексты ҚАЗ / РУС / ENG, переводы названий типов нарушений
  app.js       логика: маршруты, пакет, уведомления, отчёт, разбор, печать, история, сводка
  demo.js      демо-адаптер: те же методы, что у API, но в памяти браузера (для превью без сервера)
  icons.json   пиксельные SVG (воксельный логотип OKO, иконки)
  fonts/       Monocraft (SIL OFL 1.1)
```

Сборщик не нужен: `app/page.py` собирает страницу из этих файлов и пересобирает её при
изменении любого из них. Чтобы получить статическое демо без сервера:
`python scripts/build_preview.py` → `preview.html`.

## Нормативные источники и как они связаны с видео

- **НБ-231** — Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей (постановление Правления НБРК от 29.11.2019 № 231). [adilet](https://adilet.zan.kz/rus/docs/V1900019680)
- **НБ-14** — Правила организации охраны и устройства помещений банков второго уровня… (постановление Правления НБРК от 24.02.2020 № 14). [adilet](https://adilet.zan.kz/rus/docs/V2000020075)
- **НБ-49** — Правила осуществления обменных операций с наличной иностранной валютой в РК (постановление Правления НБРК от 04.04.2019 № 49). [adilet](https://adilet.zan.kz/rus/docs/V1900018545)
- Законы о ПОД/ФТ (№ 191-IV), о банках (№ 2444), о персональных данных (№ 94-V) — фон и аргументы для питча.

Принцип: детектор называет тип → каталог подставляет документ, пункт и цитату → в ответ API
попадают **только сверенные пункты**. Если у типа нет ни одного сверенного пункта, эпизод уходит
«на проверку» и в API не появляется.

Перед сдачей сверьте вручную:

- 17.10.2026 по zakon.uchet.kz проверены НБ-231 п. 12, 19, 20, 22, 24, 25, 31, 41, 42, 75, 76, 98, 99,
  НБ-14 п. 8 и п. 16 подп. 1), 3), 4), 6), НБ-49 п. 11 подп. 2) и п. 41.
- В НБ-14 у пункта 16 подпункты 1)–7), а не «16.1». Ссылайтесь как «п. 16 подп. 6)».
- НБ-231 менялся в 2026 году (№ 25 от 16.03.2026, № 78 от 30.06.2026). Перепроверьте нумерацию на adilet.zan.kz.
- Не сверены НБ-231 п. 106, 107, 109, прил. 4 и НБ-49 п. 54. Они помечены `verified=False` и в ответ не попадают.

## Ограничения и известные ошибки

- Реализован один детектор — «камера перекрыта» (V13, без обучения). Остальные типы ждут детекторов команды.
- `obstruction` может сработать на резкое затемнение всей сцены (выключили свет). Пороги проверьте на датасете.
- Пикселизация лиц по каскаду Хаара почти не находит лица при виде сверху. Передавайте рамки голов из своего детектора (`Box(kind="face")`).
- Видео в HEVC (H.265) некоторые браузеры не проигрывают. Тогда «Смотреть» показывает кадры клипа с сервера.
- Уведомления приходят, пока вкладка OKO открыта (в фоне — тоже). Нужен HTTPS или `localhost`.
- Незавершённые задачи теряются при перезапуске сервера и помечаются как ошибка. Готовые результаты переживают перезапуск.
- Интерфейс без авторизации (FAQ п. 27). API — только по ключу.
- Описания эпизодов и тексты норм всегда на русском, даже в интерфейсе на казахском или английском.
- Для нарушений «по бездействию» договоритесь о единой точке таймкода.
